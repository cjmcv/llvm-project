# NT 中文注释 Skill

按用户长期形成的偏好,为源码文件添加以 `// <NT>` 起头的中文注释。所有函数级注释只用一行 `<NT>` 起始,后续行不再重复;文件级注释用三段式结构。

## 何时使用

- 用户说: "加 NT 注释"、"中文注释"、"用 NT 风格"、"以 <NT> 开头"
- 用户要求: 给某个 C/C++/LLVM 源文件加注释
- 用户强调: 中文、一句话、关键字标记

## 何时不要使用

- 用户只想要英文注释 → 不触发
- 用户要生成文档 (markdown / rst) → 不触发
- 用户只问代码理解、不需要写注释 → 不触发

## 注释标记规范

```
每段注释以 // <NT> 开头(只写一次,在第一行)
后续行不再重复 <NT>
函数级注释写在函数定义之前一行
文件级注释写在 license 头之后、#include 之前
类成员之间用空行隔开
```

## 注释内容三要素

每个函数级 `<NT>` 注释必须覆盖:

```
① 函数职责: 一句话说清这个函数干什么
② 调用上下文: 在哪里被调用、上游输入、下游输出
③ 关键机制: 为什么这么写 / 在流水线哪个环节起作用
```

可选补充: 关键算法名、引用的 TableGen 产物、配对函数名。

## 语言与风格

```
语言: 简体中文
技术词: 英文术语保留 (MCInst / Pat / Predicate / Relax / TLS / VTYPE / Subtarget 等)
长度: 函数级单行 ≤100 字,复杂函数 2-3 行
语气: 陈述式,不要"我们""你""应该"等
格式: 用半角标点 + 半角逗号,中文之间不断行
```

## 函数选优先级

```
重点(必注):
  - 主入口 / 顶层调度
  - 合法性把关 / 错误诊断
  - 关键伪指令展开 / 链接器交互
  - ABI / TLS / Relax 路径
  - 汇编指令 (.directive) 解析

跳过(不注):
  - 与主流程无关的纯分支辅助
  - 调试用辅助函数
  - 第三方兼容代码块
```

## 文件级注释结构(license 头之后)

```
//===-- 文件名 - 简要说明 -===//
// ... license / SPDX ...
//===----------------------------------------------------------------------===//
//
// <NT> 文件简介: 定位(LLVM 哪一层)、输入输出、上游调用方、下游接收方。
// 上游 / 下游 / 关键机制。
//
// <NT> 关键函数串联(从顶层入口到执行流):
//   顶层入口:
//     foo()          描述
//       └─> bar()    描述
//             ├─ 路径 A
//             └─ 路径 B
//
//   寄存器解析 / 表达式 / 立即数加载 / 伪指令展开 / 汇编指令 / 错误诊断:
//     baz()          描述
//
// <NT> 总结:
//   三大职责 + 推荐阅读顺序 + 注释标记说明。
//
//===----------------------------------------------------------------------===//
```

文件级注释**只在第一节、关键函数串联节、总结节**各加一个 `<NT>`,中间普通行不加。

## ASCII 调用图约定

```
└─>   串接调用
├─    并列分支一
└─    并列分支二
│     竖线连接
```

主流程用树形,分类清单用平铺。

## 工作流程

1. **读文件总览**: `wc -l`、扫函数签名、识别 license 头位置
2. **规划函数清单**: 列出"重点函数 / 跳过函数",用户可见地展示
3. **写文件级注释**: 三段式,插在 license 之后
4. **批量插函数级注释**: 按行号倒序 / 自下而上,避免行号漂移
5. **验证**: `grep -c '^// <NT>' FILE` 检查数量,展示列表

## 编辑策略

- 用 `Edit` 工具,`old_string` 取函数签名行作为定位锚点
- 一次只插一条 `<NT>` 注释,避免大段替换失败
- 不改 license / SPDX / 现有注释
- 函数级 `<NT>` 不带空行夹在函数定义前

## 输出与对话

- 完成后给出"插入了 N 条 `<NT>` 注释"的总结
- 列出跳过的函数及原因
- 不要把注释内容复制到对话里(用户已经能从 grep 看到)
- 不需要生成任何 markdown 文档(用户偏好直接改源文件)

## 反例(不要这样写)

```cpp
// <NT> 这个函数用来解析立即数
// <NT> 它会被 parseInstruction 调用
// <NT> 输入是一个字符串
int foo(...) { ... }     // ❌ 每行都加了 <NT>

// <NT> foo
int foo(...) { ... }     // ❌ 没讲做什么

// 我们建议你应该在此处添加立即数解析逻辑
int foo(...) { ... }     // ❌ 用"我们""应该"
```

## 正例

```cpp
// <NT> 立即数加载的统一入口: 给定目标寄存器和 64 位常数, 自动选择最短的
// LUI/ADDI/SLLI 序列 (1-8 条指令); 拆分算法见 RISCVMatInt::splitImm,
// 这是 RV64 上 li 伪指令的最终落地.
void RISCVAsmParser::emitLoadImm(MCRegister DestReg, int64_t Value, ...);
```
